### ЭТАП 0: Подготовка машины Cloud-ADM

**Цель:** Подготовить рабочее место администратора .

**1. Создание ВМ (в интерфейсе OpenStack или CLI):**

* **Имя:** `Cloud-ADM`
* 
**Flavor:** 2 vCPU, 4GB RAM, 30GB Disk.


* 
**Image:** `alt-workstation-10.4-p10-cloud`.


* **Сеть:** Подключить к внешней сети, назначить **Floating IP** (Плавающий IP).

**2. Настройка внутри Cloud-ADM:**
Подключись по SSH (используя ключ, указанный при создании) и выполни настройки.

```bash
# Переходим в рута
su -

# 1. Установка RDP (xrdp) и окружения
apt-get update
apt-get install -y xrdp xorg-x11-server-Xorg xorg-x11-drivers
systemctl enable --now xrdp

# 2. Настройка пользователя altlinux и пароля
# По заданию пользователь уже должен быть altlinux (из cloud-init), задаем пароль
passwd altlinux
# Вводим: P@ssw0rd

# 3. Генерация SSH-ключей для управления другими ВМ без пароля
# Выходим из root в пользователя altlinux
exit 

# Генерируем ключ (нажимаем Enter на все вопросы)
ssh-keygen -t rsa -f /home/altlinux/.ssh/id_rsa -N ""

# Сохраняем приватный ключ на рабочий стол (как просят в задании) для PuTTY
cp /home/altlinux/.ssh/id_rsa /home/altlinux/Desktop/cloud-adm.pem

```

**3. Настройка PuTTY (на твоем физическом ПК):**

* Создай сессию `Cloud-ADM`.
* IP: Плавающий IP машины Cloud-ADM.
* Connection -> SSH -> Auth: Укажи путь к скачанному `.pem` ключу (возможно, придется конвертировать в `.ppk` через PuTTYgen, если версия старая, но новые поддерживают PEM).
* Connection -> Data -> Auto-login username: `altlinux`.

### ЭТАП 1: Project_01 (Автоматизация)

Все скрипты создаем в папке `/home/altlinux/Projects/Project_01` .

**ВНИМАНИЕ:** Перед запуском тебе нужно узнать ID образа, ID сети и ID флейвора в твоем облаке командой `openstack image list`, `openstack network list`, `openstack flavor list`.

#### Скрипт 1: `deploy_project_01.sh`

Создает инфраструктуру .

```bash
#!/bin/bash

# --- ПЕРЕМЕННЫЕ (ЗАМЕНИ НА СВОИ!) ---
IMG_ID="<ID_ОБРАЗА_alt-p11-cloud>"
NET_ID="<ID_СЕТИ_Cloud-Network>"
FLAVOR="<ID_FLAVOR_1CPU_1RAM_10DISK>"
KEY_NAME="<ИМЯ_КЛЮЧА_В_OPENSTACK>" # Тот же, что на Cloud-ADM, чтобы пускало по ключу
SEC_GROUP="default" # Или своя группа безопасности

# 1. Создание балансировщика
echo "Создаем haproxy01..."
openstack server create --image $IMG_ID --flavor $FLAVOR --nic net-id=$NET_ID --key-name $KEY_NAME --security-group $SEC_GROUP haproxy01

# 2. Создание игровых серверов (цикл)
echo "Создаем game-сервера..."
for i in 01 02 03; do
    openstack server create --image $IMG_ID --flavor $FLAVOR --nic net-id=$NET_ID --key-name $KEY_NAME --security-group $SEC_GROUP game$i
done

# 3. Назначение Floating IP для HAProxy
# Ищем свободный IP или создаем новый
FIP=$(openstack floating ip create public -f value -c floating_ip_address)
echo "Назначаем плавающий IP: $FIP на haproxy01"
openstack server add floating ip haproxy01 $FIP

echo "Ожидание запуска ВМ (30 сек)..."
sleep 30

```

#### Скрипт 2: `configure_project_01.sh`

Настраивает Docker, Приложение и HAProxy .

Для выполнения этого этапа у тебя должен быть скачан архив с приложением (ссылка из задания ) и переименован, например, в `app.zip`.

```bash
#!/bin/bash

# Получаем IP адреса (внутренние)
HA_IP=$(openstack server show haproxy01 -f value -c addresses | awk -F= '{print $2}' | awk '{print $1}')
G1_IP=$(openstack server show game01 -f value -c addresses | awk -F= '{print $2}')
G2_IP=$(openstack server show game02 -f value -c addresses | awk -F= '{print $2}')
G3_IP=$(openstack server show game03 -f value -c addresses | awk -F= '{print $2}')

SSH_OPT="-o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null"

# --- ФУНКЦИЯ НАСТРОЙКИ GAME-НОД ---
configure_game_node() {
    NODE_IP=$1
    NAME=$2
    echo "Настройка $NAME ($NODE_IP)..."
    
    # Копируем архив с приложением
    scp $SSH_OPT app.zip altlinux@$NODE_IP:/tmp/
    
    ssh $SSH_OPT altlinux@$NODE_IP << EOF
        sudo apt-get update
        sudo apt-get install -y docker-ce unzip
        sudo systemctl enable --now docker
        
        # Распаковка
        mkdir -p /home/altlinux/app
        unzip /tmp/app.zip -d /home/altlinux/app
        cd /home/altlinux/app
        
        # Создание Dockerfile (Мультистейджинг!)
        cat << DOCKER > Dockerfile
# Stage 1: Build
FROM python:3.9-alpine as builder
WORKDIR /app
COPY . .
# Если есть requirements.txt
# RUN pip install --no-cache-dir -r requirements.txt

# Stage 2: Runtime
FROM nginx:alpine
COPY --from=builder /app /usr/share/nginx/html
# Копируем конфиг nginx если нужен, или просто статику
DOCKER

        # Сборка и запуск
        sudo docker build -t game-app .
        sudo docker run -d -p 80:80 --restart always --name game game-app
EOF
}

# Запуск настройки game-нод
configure_game_node $G1_IP "game01"
configure_game_node $G2_IP "game02"
configure_game_node $G3_IP "game03"

# --- НАСТРОЙКА HAPROXY ---
echo "Настройка HAProxy ($HA_IP)..."
ssh $SSH_OPT altlinux@$HA_IP << EOF
    sudo apt-get update
    sudo apt-get install -y haproxy openssl

    # Генерация самоподписанного сертификата
    # Требование: game.au.team
    sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
        -keyout /etc/ssl/private/game.key \
        -out /etc/ssl/certs/game.crt \
        -subj "/C=RU/ST=Moscow/L=Moscow/O=Skills/CN=game.au.team"
    
    # Объединяем для HAProxy
    cat /etc/ssl/certs/game.crt /etc/ssl/private/game.key | sudo tee /etc/ssl/private/game.pem

    # Конфиг HAProxy
    cat << CFG | sudo tee /etc/haproxy/haproxy.cfg
global
    log /dev/log local0
    log /dev/log local1 notice
    chroot /var/lib/haproxy
    stats socket /run/haproxy/admin.sock mode 660 level admin expose-fd listeners
    stats timeout 30s
    user haproxy
    group haproxy
    daemon

defaults
    log global
    mode http
    option httplog
    option dontlognull
    timeout connect 5000
    timeout client  50000
    timeout server  50000

# Статистика (по заданию /haproxy?stats)
listen stats
    bind *:8404
    stats enable
    stats uri /haproxy?stats
    stats refresh 10s
    # Можно добавить stats auth admin:password если нужно

# Frontend
frontend https_front
    bind *:443 ssl crt /etc/ssl/private/game.pem
    mode http
    default_backend game_backend

# Backend
backend game_backend
    mode http
    balance roundrobin
    option forwardfor
    http-request set-header X-Forwarded-Port %[dst_port]
    server game01 $G1_IP:80 check
    server game02 $G2_IP:80 check
    server game03 $G3_IP:80 check
CFG

    sudo systemctl restart haproxy
EOF

# Добавляем запись в /etc/hosts на Cloud-ADM для проверки
echo "$HA_IP game.au.team" | sudo tee -a /etc/hosts

```

### ЭТАП 2: Project_02 (Кибер Бэкап)

Здесь меньше скриптов, больше установки ПО. Образы ВМ: `alt-p11-cloud-x86_64`.

**1. Развертывание ВМ:**
Создай 3 машины вручную или скриптом: `ACM-Server`, `DB-Server`, `BAR-Agent01`.

2. Настройка ACM-Server (Сервер управления): 
Подключись по SSH.

```bash
# Установка PostgreSQL (нужна для сервера управления)
apt-get update
apt-get install -y postgresql
systemctl enable --now postgresql

# Установка Кибер Бэкап
# Файл установщика (обычно .x86_64) должен быть предоставлен организаторами.
# Допустим, он называется 'cyber-backup.x86_64'.
chmod +x cyber-backup.x86_64
./cyber-backup.x86_64

```

* **В меню установщика:** Выбери "Сервер управления" (Management Server).
* **СУБД:** Укажи "Использовать внешнюю PostgreSQL" -> localhost.
* **Пользователь веб-консоли:** Установщик может спросить создание пользователя или использовать системного. По заданию вход под `root` с паролем `toor`. Убедись, что у root в системе пароль `toor` (`passwd root`).
* **Порт:** Убедись, что веб-интерфейс на `9877`.

3. Настройка DB-Server: 

```bash
apt-get install -y postgresql
systemctl enable --now postgresql

# Запуск установщика
./cyber-backup.x86_64
# Выбрать: Агент для PostgreSQL (Agent for PostgreSQL) и Агент для Linux.

```

**Регистрация агента:**


### ЭТАП 3: Project_03 (Docker Swarm)

ВМ: `master01`, `worker01`, `worker02` .

1. Инициализация кластера (на master01): 

```bash
ssh altlinux@<IP_MASTER>
sudo -i

# Инициализация
docker swarm init
# Скопируй команду с токеном, которая появится (docker swarm join --token ...)

```

**2. Подключение воркеров:**
Зайди на `worker01` и `worker02` и выполни скопированную команду `docker swarm join ...`.

3. Настройка Master Node: 

```bash
# Запрет запуска контейнеров на мастере (drain)
docker node update --availability drain master01

```

4. Поднятие локального Registry: 

```bash
# На master01
docker service create --name registry --publish published=5000,target=5000 registry:2

```

*Важно:* Чтобы кластер мог работать с локальным registry без HTTPS, на **всех** нодах в `/etc/docker/daemon.json` нужно добавить:

```json
{ "insecure-registries": ["<IP_MASTER>:5000"] }

```

И перезапустить docker: `systemctl restart docker`.

5. Запуск стека приложения: 
Создай файл `docker-compose.yml` на `master01`:

```yaml
version: '3.8'

services:
  web:
    image: nginx:latest  # Или образ из приложения
    deploy:
      replicas: 2
      placement:
        constraints:
          - node.role == worker
    ports:
      - "80:80"
      - "443:443"
    # Для HTTPS нужно прокинуть сертификаты через volumes или secrets
    # volumes:
    #   - /etc/ssl/certs:/etc/ssl/certs
    
  redis:
    image: redis:alpine
    deploy:
      replicas: 1
      placement:
        constraints:
           - node.role == worker

  db:
    image: postgres:13
    environment:
      POSTGRES_PASSWORD: example
    deploy:
      replicas: 1
      placement:
        constraints:
           - node.role == worker

```

**Запуск стека:**

```bash
docker stack deploy -c docker-compose.yml school-site-project

```

**Проверка:**
Добавь в `/etc/hosts` на Cloud-ADM запись `<IP_ЛЮБОГО_ВОРКЕРА> school-site.au.team` и проверь доступ через браузер.
