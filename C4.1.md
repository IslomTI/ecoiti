В моих инструкциях (особенно в скриптах Bash и Ansible) я использовал заглушки в угловых скобках, например `<ID_ОБРАЗА>`. Это переменные, которые уникальны для каждого облака и стенда.

**Ты ОБЯЗАН заменить их на реальные данные перед запуском, иначе скрипты упадут с ошибкой.**

Вот список всех заглушек и команды, которыми ты можешь узнать реальные значения в консоли OpenStack (на машине `Cloud-ADM` или локально, если есть доступ).

### 1. Ресурсы OpenStack (Самые важные)

Эти данные нужны для скрипта `deploy_project_01.sh` и Ansible.

| Заглушка в коде | Что это | Команда для поиска (в терминале) | На что смотреть в выводе |
| --- | --- | --- | --- |
| `<ID_ОБРАЗА_...>` | ID образа ОС (Image) | `openstack image list` | Колонка **ID**. Ищи имя `alt-p11-cloud...` или `alt-workstation...` |
| `<ID_FLAVOR_...>` | ID размера ВМ (Flavor) | `openstack flavor list` | Колонка **ID**. Ищи подходящий по RAM/CPU (например, `m1.small` или `basic-1-1-10`) |
| `<ID_СЕТИ_...>` | ID внутренней сети | `openstack network list` | Колонка **ID**. Ищи сеть типа `Cloud-Network`, `net-fixed` или `private` |
| `<ИМЯ_КЛЮЧА_...>` | Имя SSH-ключа | `openstack keypair list` | Колонка **Name**. Обычно это тот ключ, что ты создал или загрузил |
| `<SEC_GROUP>` | Группа безопасности | `openstack security group list` | Колонка **Name** или **ID**. Обычно `default` (если в ней открыты порты) |

### 2. IP-адреса и Сеть

Эти данные нужны для настройки соединений (SSH, Docker Swarm, Кибер Бэкап).

| Заглушка | Откуда взять |
| --- | --- |
| `<Floating_IP_Cloud-ADM>` | **Снаружи:** `openstack server list` (смотри колонку Networks, там будет два IP, тебе нужен публичный).<br>

<br>**Внутри:** `curl ifconfig.me` |
| `<IP_MASTER>`, `<IP_WORKER>` | **Снаружи:** `openstack server list` (бери внутренние IP, обычно начинаются на 192.168... или 10.x.x.x).<br>

<br>**Внутри ВМ:** `hostname -I` |
| `<IP_ACM_SERVER>` | IP сервера, где стоит "Кибер Бэкап" (Management Server). Узнать через `openstack server list`. |

### 3. Docker Swarm Токен

Этот токен генерируется только один раз при создании кластера.

* **Заглушка:** `<ВАШ_ТОКЕН>` или `<TOKEN>`
* **Где взять:**
1. Когда ты запускаешь на мастере `docker swarm init`, токен выводится на экран.
2. **Если потерял:** Зайди на мастер-ноду (`master01`) и введи:
```bash
docker swarm join-token worker

```


Он покажет полную команду для подключения воркеров.

### 4. Пароли для Ansible

В плейбуках Ansible пароль пользователя нельзя писать открытым текстом в поле `password`, нужен хеш.

* **Заглушка:** `...GENERATE_YOUR_OWN_HASH...`
* **Как получить хеш:**
На любой Linux машине (например, Cloud-ADM) выполни:
```bash
# Для пароля P@ssw0rd
openssl passwd -6 'P@ssw0rd'

```


Или, если есть утилита `mkpasswd`:
```bash
mkpasswd -m sha-512 'P@ssw0rd'

```


Полученную длинную строку (начинается на `$6$...`) вставь в Playbook.

### Пример замены в скрипте

**Было в скрипте:**

```bash
IMAGE_ID="<ID_ОБРАЗА_alt-p11-cloud>"
NET_ID="<ID_СЕТИ_Cloud-Network>"

```

**Ты делаешь:**

1. Пишешь `openstack image list` -> видишь ID `74a2050e-5627-4401...`
2. Пишешь `openstack network list` -> видишь ID `a1b2c3d4-...`

**Стало в скрипте:**

```bash
IMAGE_ID="74a2050e-5627-4401-b8d1-1234567890ab"
NET_ID="a1b2c3d4-1234-5678-90ab-cdef12345678"

```

*(Кавычки оставляй, угловые скобки `< >` убирай!)*
