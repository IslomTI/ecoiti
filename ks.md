В EcoRouter есть особенность: он очень чувствителен к порядку команд и типу аргументов. Если консоль «не видит» команду tunnel, скорее всего, она либо ждет, что вы сначала укажете режим работы туннеля, либо вы пытаетесь указать IP-адрес там, где роутер ждет имя интерфейса.
Попробуйте применить команды в следующем порядке и с изменениями:
1. Сначала задайте режим (Mode)
EcoRouter иногда не понимает команды source и destination, пока не узнает, что это за тип туннеля.
Внутри интерфейса Tunnel1 введите команду режима первой:
interface Tunnel1
 tunnel mode gre ip

После этого команды source/destination должны стать доступными.
2. Используйте имя интерфейса в Source
EcoRouter (в отличие от Cisco IOS) часто требует указывать в качестве источника (source) физический интерфейс, а не его IP-адрес.
Вместо IP-адреса (например, 178.207.179.4), укажите имя внешнего порта, через который этот IP работает:
# Неверно (частая ошибка в EcoRouter):
tunnel source 178.207.179.4

# Верно:
tunnel source gigabitethernet0/0

(Замените gigabitethernet0/0 на ваш реальный внешний интерфейс, смотрящий в сторону ISP).
Итоговый правильный конфиг для rtr-cod:
conf t
interface Tunnel1
 ! Сначала режим
 tunnel mode gre ip
 ! Затем параметры
 ip address 10.10.10.1 255.255.255.252
 ! Источник - имя физического интерфейса (WAN)
 tunnel source gigabitethernet0/0
 ! Назначение - IP-адрес удаленного роутера (WAN IP офиса)
 tunnel destination 178.207.179.28
 ! Не забываем MTU, чтобы пакеты не дропались (рекомендация)
 ip mtu 1400
 ip tcp adjust-mss 1360
 no shutdown
exit

Проверка:
После ввода нажмите ? внутри интерфейса Tunnel1. Если вы видите tunnel в списке, значит, вы все делаете верно. Если нет — проверьте, правильно ли написано название интерфейса при создании (EcoRouter чувствителен к регистру: Tunnel1 vs tunnel1). Лучше используйте interface Tunnel1.
